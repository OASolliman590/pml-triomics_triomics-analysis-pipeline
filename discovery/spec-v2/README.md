Base commit: `c8f0eeca520ee44cc730a35d37ce4e7f85dcd379`.  
**State: content-locked release candidate; independent Astra freeze audit pending.**
The specification defines what to implement. It does not assert that any package,
scientific validation, real-data analysis or named-agent run has already happened.

## Outcome and scope

Build a local, reproducible CLI + self-contained HTML report over quantified
feature-by-sample data. Support independent two/multiple groups, continuous
molecular-response associations, verified paired changes and qualified repeated
models. Retain all three molecular profiles, arbitrary block counts, typed
clinical metadata, concatenation baselines, categorical DIABLO, continuous
block.spls and MOFA2. Interpret targets with explicit evidence limits.

No raw-MS processing, new statistical method, web app, guessed clinical mappings,
causal certification, direct-binding inference from abundance data, or automatic
access to restricted reference databases. One block can be validated/analyzed;
integration needs at least two eligible blocks. Three is a default, never a limit.

## Freeze and execution

`freeze.json` records pending independent audit, not a fabricated review.
`FILE_MANIFEST.json` pins delivered files. Sol first verifies those files and the
actual repository state, obtains one bounded Astra low spec audit, resolves P0/P1
correctness blockers, records any amendment, and freezes the reviewed content hash.
Only then dispatch coding. Acceptance evidence is generated by implementation,
not required to exist before the implementer writes its first test.

The 41 packets are the retained programme. Runtime-qualified functionality and
scientifically conditional extensions are distinguished in each card. A conditional
route may remain blocked without preventing unrelated work; it is never silently
counted as completed. The final close report distinguishes scope delivered,
remaining programme work, and real-data validation not performed.

## Supplied data

Only four planning Markdown files were attached to this task. No original assay
matrices or clinical workbook were available to validate here. The two example
studies in this kit are explicitly synthetic software fixtures, not reconstructions
of the user's data and not evidence of method performance. Real-data onboarding
uses A's source/dictionary/identity gate on the authorized execution host.
