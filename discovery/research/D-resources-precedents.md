## Most consequential findings

- The claim that the named predecessors uniformly omit lipidomics is not defensible. MultiOmicsIntegrator documents a `lipidr = true` lipidomics analysis, and an official OmicsAnalyst tutorial uses lipidomics plus RNA-seq. The amount of lipid-specific interpretation these provide still needs inspection.
- The statement that mixOmics has no design handling is false: it explicitly provides repeated-measure decomposition. MOFA2 has feature-set enrichment, so it does not merely stop at feature lists.
- GO annotations concern gene products; GO must not be treated as an interchangeable compound reaction database. Reactome prefers ChEBI for small molecules. ChEBI therefore needs its own proposed dependency/access review before a Reactome compound route is made concrete.
- KEGG must remain conditional. Public API access is limited to academic users and academic use, with a published three-calls-per-second limit. Public access is not a redistribution licence.
- LION/web explicitly prohibits confidential uploads. A local route can be investigated through its published source, but software and ontology artefacts need separately pinned provenance and licence checks.
- Lipid sum composition is a level of chemical identification, not an exact structure. Neither “all lipids map” nor “lipid shorthand maps nowhere” is an acceptable universal claim.

These bullets summarize the question records below; the records supply their evidence and limits.

## Question ledger: access, identifiers and route constraints

### D-Q01 — Can KEGG be an unconditional dependency or redistributed cache?

**Proposed answer / classification:** Verified fact: KEGG copyright belongs to Kanehisa Laboratories. Academic website use is allowed; academic service providers are requested to obtain the applicable provider licence. Non-academic use requires a commercial licence. Public REST access is academic-only. **Inference:** a software client licence does not establish rights in returned KEGG content. **Design choice proposed:** route disabled until user entitlement and intended deployment are recorded; no KEGG bulk data, maps or derived redistributable cache in Git or Notion absent resource-specific permission.

**Evidence:** [KEGG Copyright and Disclaimer](https://www.genome.jp/kegg/legal.html), sections “Academic use” and “Non-academic use”, last updated 2024-10-01 (`DOC`/primary indexed text); [KEGG API](https://www.genome.jp/kegg/rest/), “Restriction”, rate limit and update history, last updated 2026-06-17 (`DOC`); [Pathway Solutions licensing](https://kegg.net/en/licensing.html), End User and Service Provider sections (`DOC`); [licensing FAQ](https://kegg.net/en/licensing_faq.html), sections 1-1 through 1-4 and 2-1 (`DOC`). Commercial EULA type 1 addresses internal FTP use; type 2 adds mirror web/API access. Provider licensing is separate.

**Uncertainty / contradiction:** Current signed institutional terms are unknown. The [academic subscription agreement](https://kegg.net/doc/agreement_eu.pdf) direct open failed; no clause-by-clause assertion about that agreement is made. General public pages do not settle the proposed product's downstream caching, redistribution or service-provider classification. Fees are not established here. **Impact/status:** conditional route, terms verification incomplete. Reopen with exact applicable agreement or written permission covering access, caching and distribution; then perform allowed tiny API checks. This is not a finding that KEGG cannot be used at all.

### D-Q02 — What is the KEGG API contract?

**Answer / classification:** Verified documentation: API general form is `https://rest.kegg.jp/<operation>/<argument>[/...]`; GET accepts up to ten entries, with one pathway for image/KGML requests. Compound identifiers use C numbers. CONV gene inputs include UniProt; chemical conversion supports PubChem and ChEBI, not a documented generic HMDB or lipid-shorthand input. INFO reports database release information. Calls must not exceed three per second.

**Evidence:** [API Manual](https://www.kegg.jp/kegg/rest/keggapi.html), “Naming conventions”, “INFO”, “GET”, “CONV” (`DOC`, live manual inspected; no separate version string); rate limit in D-Q01. **Verification artifact:** inspected manual, no API request made. **Uncertainty:** no current release was obtained; mapping success and one-to-many behaviour remain untested. **Impact/status:** preserve namespace-qualified input and all mappings; do not invent direct HMDB conversion. Conditional and pending executable verification.

### D-Q03 — What can Reactome supply, and under what terms?

**Answer / classification:** Verified fact: current licence section 1(c) dedicates data and derived data files under CC0; 1(a) applies CC BY 4.0 to illustrations/icons/art; 1(b) generally applies Apache 2.0 to software with explicit exceptions. FoamTree has special local-installation conditions. Annotation and code must not be assigned one blanket licence.

**Evidence:** [current License Agreement](https://reactome.org/license), sections 1(a-c), 2(a) (`DOC`; page revision date unknown). [Analysis Tools](https://reactome.org/userguide/analysis/), “Identifier mapping” (`DOC`): UniProt protein IDs, ChEBI small-molecule IDs, HGNC/Ensembl gene identifiers preferred; isoform suffixes affect mapping. [Download](https://reactome.org/download-data), “Services and Repositories” (`DOC`): release-specific Zenodo files available from v89, June 2024.

**Uncertainty / contradiction:** The 2017 [licensing announcement](https://reactome.org/about/news/97-updated-license-agreement) differs on software and database dumps; current agreement governs this provisional assessment. Current release and measured coverage remain unknown. Reactome entity context and mappings need tests before collapsing isoforms or compartments. **Impact/status:** promising open-data route, but identifier mapping/runtime coverage pending; retain original IDs, species and mapping multiplicity. ChEBI is a dependency proposal requiring its own review, not an installed addition.

### D-Q04 — Is GO a direct metabolite reaction annotation route?

**Answer / classification:** Verified fact: standard GO annotations connect a gene product to a GO term and include evidence/reference information. GO's aspects are molecular function, biological process and cellular component. **Inference:** assigning a measured metabolite directly to a gene-product enrichment universe via a reaction-associated gene changes the unit of analysis; such conversion needs an explicit rule and cannot be silently called metabolite GO enrichment.

**Evidence:** [Introduction to GO annotations](https://www.geneontology.org/docs/go-annotations/), “Standard GO annotations”, “NOT modifier” and open-world principle (`DOC`); [GO citation policy](https://geneontology.org/docs/go-citation-policy/), “License” and “Attribution” (`DOC`), CC BY 4.0 with release-specific attribution requested. Software has separate licences.

**Uncertainty:** precise pinned ontology/annotation release and organism coverage unknown. Absence of annotation is not evidence of biological absence. **Impact/status:** revise D's terminology before spec: a gene-product functional route alongside reaction-network mapping. Preserve evidence codes and negation; never count a NOT annotation as positive membership. Proposed design, not yet adopted.

### D-Q05 — Can UniProt data and identifiers be used?

**Answer / classification:** Verified fact: copyrightable database material is CC BY 4.0; the disclaimer notes possible patents/other rights. [UniProt licence](https://www.uniprot.org/help/license/), “License”/“Disclaimer”, modified 2024-12-18 (`DOC`). Reactome's identifier mapping documentation supports UniProt and explains isoform suffixes (D-Q03).

**Uncertainty:** current release, deleted/secondary accession handling, ID-mapping API signatures and actual coverage unverified here. The official accession-numbers help page returned only a JavaScript/network fallback, so it did not verify accession semantics. **Impact/status:** attribution-capable mapping route provisionally feasible. Before implementation, pin release and verify current/secondary/deleted/isoform examples without merging different proteins solely by name. Species and original namespace must remain visible.

### D-Q06 — Is HMDB freely redistributable for every downstream use?

**Answer / classification:** Verified published statement: HMDB is publicly available, but commercial use and redistribution, in whole or part, require explicit author permission and acknowledgment. [Citing HMDB](https://hmdb.ca/citing), opening terms and footer (`INDEX`; direct opens returned internal errors). Footer states HMDB Version 5.0; cited reference is HMDB 5.0 for 2022. Bibliographic DOI resolution remains pending: the attempted resolver open failed, and no DOI is accepted here solely from recollection or secondary citations.

**Uncertainty:** no current dated download was inspected. Noncommercial packaging/caching terms and sublicensing into a generally reusable package are not established by “freely available”. Coverage is human-metabolome oriented, not evidence every chemical input has a match. **Impact/status:** conditional mapping resource; do not bundle a general-purpose HMDB cache until intended reuse is established. User-supplied permitted mappings are a design alternative, with provenance required.

### D-Q07 — What does RefMet standardize, and is the database licence established?

**Answer / classification:** Verified documentation: RefMet distinguishes exact structures and lower-resolution metabolite species, including lipid sum-composition examples. [Fahy and Subramaniam 2020](https://www.nature.com/articles/s41592-020-01009-y), annotations groups, DOI 10.1038/s41592-020-01009-y, version of record 2020-11-16 (`DOC`). [Official repository](https://github.com/metabolomicsworkbench/RefMet), Overview/Usage, `refmet_map`, `refmet_map_df`, `refmet_metadata` (`SOURCE`); [DESCRIPTION](https://github.com/metabolomicsworkbench/RefMet/blob/main/DESCRIPTION) reports package 1.0.0; repo identifies an MIT licence.

**Uncertainty:** software MIT status does not automatically establish remote database content redistribution. [RefMet portal](https://www.metabolomicsworkbench.org/databases/refmet/index.php) was inspected, but a specific database licence/release and exact function formal arguments were not resolved. Main-branch SHA is unpinned. **Impact/status:** useful nomenclature adapter candidate; database redistribution remains unknown. Keep structural resolution explicit, and do not resolve a sum composition into an arbitrary exact isomer. No package/API run occurred.

### D-Q09 — Is LION available for confidential analysis and arbitrary designs?

**Answer / classification:** Verified fact: web terms forbid confidential/proprietary uploads. Ranking-mode input requires lipid names, numeric concentration columns, condition and sample identifiers; the FAQ specifies at least two conditions and two samples per condition. Optional sharing of unmapped names is described. Local R/Shiny code is available. [LION/web FAQ](https://www.lipidontology.com/faq.html), “Terms of usage”, “Input”, “About” (`DOC`, page version unknown). [Molenaar et al.](https://pmc.ncbi.nlm.nih.gov/articles/PMC6541037/), “Availability of source code” and supporting data, DOI 10.1093/gigascience/giz061, 2019 (`DOC`): LION-web code GPL v3; ontology OBO and database R package distributed separately.

**Uncertainty:** latest ontology/code versions, current licence on each database artefact, parser coverage and local function contract are unpinned. Numerical web ranking requirements cannot simply be assumed for a candidate-list/local-enrichment mode. **Impact/status:** hosted confidential-data route unavailable; local enrichment remains conditional, not cancelled. Reopen after source/database pinning, licence inspection and synthetic parser/enrichment checks. Do not send identifiers to optional telemetry without an explicit approved policy.

### D-Q10 — Is BioPAN an annotation lookup accepting any candidate list?

**Answer / classification:** Verified documentation: BioPAN compares two conditions in mammalian lipidomics and produces hypotheses about lipid pathway activity and relevant genes. [Official tool page](https://lipidmaps.org/resources/tools/38?task=7.3), Description/Technical Information (`DOC`). [BioPAN 1 docs](https://www.lipidmaps.org/tool/biopan/doc/index.html) and [Step 1](https://lipidmaps.org/tool/biopan/doc/step1.html), supported lipid classes and input (`DOC`). [Gaud et al. paper](https://pmc.ncbi.nlm.nih.gov/articles/PMC7848852/), version changes and operation, accepted 2021-05-20 (`DOC`/primary indexed text); source link is [OSF](https://osf.io/pkd6b/files).

**Inference:** it is not interchangeable with a lookup/enrichment adapter for an arbitrary list of selected features. Its comparison/statistics need an explicit compatible design and input intensities; inferred gene activity is a hypothesis, not an observed protein effect. **Uncertainty:** source licence and exact current local API not inspected; do not infer code licence from the article's CC BY licence or database terms. **Impact/status:** conditional specialised subroute. Retain D for arbitrary designs through other routes and report `unsupported_design` for BioPAN where appropriate; a design-specific comparison must not silently replace the study estimand.

## Proposed conditional behaviour and validation queue

These are **design choices for grilling**, not adopted interface changes:

1. Distinguish `not_configured`, `licence_unverified`, `unavailable`, `unsupported_namespace`, `unsupported_design`, `ambiguous_mapping`, `unmapped` and `success`. D must always account for every incoming feature. Infrastructure failure and zero biological enrichment are different outcomes.
2. Keep original ID/namespace, standardized ID, structural resolution, mapping source/release, target ID, organism, evidence and ambiguity on every mapping edge. Class or sum-composition mappings must not masquerade as exact structure matches.
3. Both candidate sources feed annotation, but enrichment must retain the relevant eligible background or complete ranked statistic; a selected-feature list alone is insufficient to define every enrichment analysis. BioPAN requires a distinct compatible contrast/intensity contract. These facts may require a proposed ADR to the candidate-set interface; do not silently change it.
4. Report route coverage by namespace and analysis source, losses/ambiguities, licence availability, enrichment universe/statistic, resource versions and unresolved routes. Never equate unmapped features with no biological function.
5. Minimum pending executable checks: namespace collision; one-to-many protein mapping; species mismatch; secondary/isoform accessions; parseable sum composition versus exact chains; ether/plasmalogen/adduct examples; unknown lipid preservation; zero mappings; zero enriched sets; duplicated mapping effects on universe; local-only run; mocked unavailable resources; supported/unsupported BioPAN designs. Fixtures must be synthetic and visibly labelled. No result for these checks is claimed.

Before D can be implementation-ready: settle scientific enrichment contracts; independently review these corrections against historical architecture; approve actual dependencies; pin software/data versions and terms; establish institution-specific KEGG/HMDB entitlement if used; verify local LION/BioPAN code/data licences; perform parser/mapping/enrichment checks; and document current species/identifier coverage with actual counts. A complete conditional design can proceed while these resource routes remain conditional.
