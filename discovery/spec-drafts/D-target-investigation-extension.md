# General target investigation — proposed D extension

Date: 2026-09-06. User request: generalize the drug/target idea so the pipeline can investigate arbitrary targets. Status: **proposal reviewed by Claude Opus 5 and revised by root; not implemented or adopted**. Its [separate review](../reviews/opus-target-extension-review.md) and [response](../reviews/opus-target-extension-response.md) distinguish this addition from earlier Opus checkpoints. Evidence is recorded separately in [target-investigation-evidence.md](../research/target-investigation-evidence.md). Existing A–D requirements remain; this adds a target-hypothesis interpretation service within D rather than replacing MOFA2, DIABLO/mixOmics, statistics or annotation.

## 1. Question, scope and meaning of a target

Ask: **How consistent are the observed omics changes with perturbing a specified target, what competing targets or mechanisms fit, and what evidence would distinguish them?** Investigate rather than construct a one-sided justification.

A Target is a namespace-qualified biological entity with organism and entity type: enzyme, transporter, receptor, other regulatory protein, defined protein complex or another explicitly supported entity. Drug identity is optional. A pathway/process hypothesis has its own entity type and cannot be reported as a single molecular binding target. Ambiguous names, isoforms, complexes and unsupported entities remain unresolved or unsupported instead of being coerced to a gene symbol.

The interface accepts any supplied target identifier; evidence coverage determines whether it can be evaluated. It does not promise that metabolomics identifies every target, distinguishes targets with equivalent downstream effects, or establishes physical drug binding. Nonenzymatic targets require documented signaling/regulatory or perturbation-signature links rather than invented direct reactions. A generic graph path is mechanistic context, not proof of causal transmission.

## 2. Three user modes

| Mode | User question | Required distinction |
|---|---|---|
| `assess` | Do these data support perturbation of this named target? | Hypothesis/expected effect direction specified before evaluation when confirmatory; retrospective assessment labelled exploratory. |
| `compare` | Which of these candidate targets is better supported, or are they indistinguishable? | Explicit candidate set, comparable eligible evidence/coverage, alternative explanations and ties. No forced winner. |
| `discover` | Which targets should we investigate from this response? | Bounded, versioned target universe and candidate-generation rule; findings are exploratory nominations, not independently validated targets. |

Drug-first use may obtain candidate targets from approved reference resources, then run compare. Target-first use needs no drug. Phenotype/omics-first discovery also needs no drug. Neither literature popularity nor number of database links is a default ranking score.

Require `hypothesis_status` (exploratory by default; confirmatory only with an approved prospective protocol or independent validation design), `declaration_evidence_ref`, `data_access_cutoff_ref`, `discovery_parent_refs` and a versioned request ledger. The ledger records all relevant prior requests, targets, selection decisions and reused observations across Study/analysis/run IDs; changing a name/ID does not reset evidence history. A target chosen or refined using the evaluation observations remains exploratory on those observations in assess or compare, including descriptive profiles. A prospectively fixed comparison is not automatically exploratory merely for using compare mode. Uncertain history remains exploratory. Independent validation must be explicitly linked and separate, never inferred from a later request timestamp. Ledger completeness supports review of multiplicity/selection; it does not itself control error rates.

## 3. Evidence and module ownership

Pipeline: A validated identities/measurement provenance → B explicit contrast and full eligible results → C optional cross-block factors/selections → D mapping and target investigation → D report.

- A supplies Study/source/Feature registries, aliases, coverage, units, identification resolution and selection/mask evidence through existing approved exports.
- B supplies full tested-feature results and eligible family, effect scale/direction/uncertainty, covariates, non-estimability and analysis population. The target layer never refits B, substitutes supplied q or derives direction from a p value.
- C supplies optional model/selection/stability and orientation context through public artifacts. MOFA/DIABLO agreement on the same observations is not independent replication; loadings are not treatment effects. Lack of a C fit does not alone block a metabolomics-only investigation.
- D owns target identity, context-aware reference graph/signatures, evidence chains, competing hypotheses, coverage/ambiguity, summaries and proposed follow-up evidence needs.

Existing CandidateNominations stays B/C. TargetHypotheses is a separate D-derived object with provenance back to both branches, not a new upstream candidate branch. Both original annotation routes remain active according to their resource gates. Proteomics/lipidomics can corroborate, contradict or be unavailable; none is mandatory simply to assess a metabolomics hypothesis. Block names do not choose scientific behavior.

## 4. Proposed public artifacts and configuration

| Artifact | Required fields/meaning |
|---|---|
| TargetRequest | study_id, analysis_id, request_id, mode, target namespace/ID/type/organism, optional drug ID, hypothesized perturbation (inhibition/activation/other/unknown), context and hypothesis declaration time |
| TargetContext | tissue/biofluid/cell context, exposure/contrast, sampled time/dose when available, species/compartment, covariates and alternative exposure/physiology explanations; unknowns explicit |
| TargetUniverse | versioned members/digest, eligibility and candidate-generation rule, selection provenance, included/excluded counts/reasons; assess mode still records its exact target/hypothesis set |
| TargetHypotheses | hypothesis_id, TargetRequest/ledger references, target identity and hypothesis level, expected perturbation/context, selection ancestry and hypothesis_status; D-derived, never a new B/C nomination branch |
| ExternalTargetEvidence | evidence_class (binding/functional/engagement/association), exact drug/target assignment and assignment confidence meaning, organism/context, assay ID/type/description, endpoint/value/units/relation or explicitly not-reported, validity flags, controls/limitations, original publication/dataset and experiment dependency group, release/hash |
| MechanismEvidence | edge/signature ID, target/reaction/regulator/metabolite entities, compartment, relation/direction or unknown, cited evidence type, organism/context, resource release/hash, original experiment/publication group and uncertainty |
| TargetEvidence | target hypothesis → original Feature/result references → mapping/edge/signature chain; observed versus expected effect with provenance; supporting/contradicting/ambiguous/uninformative/not_observed classification and reason; evidence dependency group |
| TargetAssessment | target/hypothesis/context/universe IDs; route/execution eligibility; evidence profile; coverage/ambiguity and alternative-target group; limitations, sensitivity results, inference method/status and references |
| TargetFollowup | unresolved distinction, needed evidence class and rationale; no invented experiment result or claim that one generic assay settles every target |

MechanismEvidence additionally requires ordered intermediate nodes/typed edges, path length, compartment, exact reaction direction state and experimentally supported versus electronic/species-inferred provenance. TargetEvidence repeats the observation quantity/scale (intensity, relative abundance, absolute concentration or separately validated flux) and compatibility with the expected quantity; a cross-metabolite intensity ratio is not an absolute substrate/product ratio. TargetAssessment references the request ledger, external evidence and an explicit comparison eligibility statement. External evidence classes and heterogeneous endpoints are never collapsed to one potency/affinity or generic support value; pChEMBL or assay assignment confidence is not converted to binding probability.

Proposed config: `target_investigation.enabled` (opt-in), `.mode`, `.targets`, `.candidate_universe_ref`, `.hypothesis_ref`, `.drug_ref` (optional), `.context_ref`, `.resources`, `.mechanism_policy`, `.signature_refs`, `.comparison_policy`, `.inference_policy`, `.completeness_policy`. Each resource/signature/decision has version/hash and approved local-use provenance. Missing required definitions fail visibly; no default target, direction, graph radius, score weights or p-value threshold is invented.

Resource adapters are conditional research items, not approved installations: Rhea/Reactome and existing UniProt/ChEBI mappings for molecular relations; ChEMBL or other verified assay resources for drug-target evidence; appropriately contextualized published perturbation signatures for nonlocal effects. Open Targets target–disease association is contextual prior evidence, not physical-binding evidence. No uploaded private measurements or identifiers are needed for designing these adapters; production network/cache policy remains explicit.

## 5. Assess evidence without inflating it

Keep three separate questions in every report: (a) metabolic compatibility with a target mechanism, (b) supporting target-perturbation/functional evidence, (c) direct drug-binding or cellular-engagement evidence. A publication/reference assay is external prior evidence, not a measurement made in this Study. Binding, functional response and cellular engagement are separately typed and retain assay qualifications; an assay-type label alone does not establish selective binding to the exact target in the study context.

A model must cite why a target perturbation predicts an effect. Reaction substrates/products alone do not justify a universal substrate-up/product-down rule. Concentration changes are not flux measurements; protein abundance is not necessarily activity; tissue/transport/feedback/compartment changes may reverse simple expectations. Unsigned relationships yield nondirectional compatibility only. When expectations are unavailable, do not label a measured change contradictory.

Report multiple credible mappings and indistinguishable targets. Lipid sum-composition ambiguity cannot become an exact mechanistic species. Shared pathways, correlated metabolites, adducts of one compound, copied database entries and B/C analyses of the same data are not independent pieces of evidence. Preserve source-study/publication and feature-dependency groups; avoid multiplying their support as if independent. Report both original feature/record counts and distinct dependency-group counts, explicitly labelled; grouped counts are not proof that groups are statistically independent. Negative or absent measurement is separated from insufficient coverage, low sensitivity and unavailable reference knowledge.

Interpretation rules depend on hypothesis level and target class. Molecular-target and pathway/process hypotheses are not ranked together. Pathway hypotheses assess pathway-level compatibility; binding/engagement and molecular specificity axes are not-applicable. Different molecular classes (e.g. enzyme versus receptor) can be compared only on explicitly common, context-compatible evidence axes; heterogeneous mechanism labels alone do not provide comparability. Require a per-comparison statement of assay and reference coverage, annotation asymmetry, eligible common evidence and losses. Material asymmetry without an approved comparison adjustment/matched protocol yields side-by-side non-comparable profiles, not a partial order or winner. A shared pathway alone cannot distinguish its molecular targets.

Assess parent drug/xenobiotic metabolites, general toxicity/stress, tissue composition, diet/microbiome and other applicable exposure/physiology explanations as potential alternatives or signature confounders. Record whether these features are included and why; drug-presence markers alone cannot establish its target mechanism. Observational contrasts stay observational, and absent exposure metadata cannot become a drug-response claim.

Default output is an **auditable evidence profile**: observed coverage, supported/contradictory/ambiguous relations, effect sizes/uncertainty where valid, specificity to alternatives, stability and evidence provenance. These are descriptive dimensions, not a binding probability or calibrated confidence. Comparison can show profiles/partial ordering and unresolved equivalence groups. A composite ranking or target-level p/q requires its own reviewed method, reference/null model, comparability and calibration protocol; no arbitrary weighted sum or probability percentage.

If a future target-level test is enabled, declare all tested target–hypothesis combinations, context, multiplicity family and selection process. D's target-level adjustment is distinct from B's per-Block FDR and never changes B q. Discovery and testing on the same data cannot become confirmation; use separately justified selection-aware inference or independent validation. Evaluation must separate reference construction, target/signature selection, tuning and assessment, including compound-family/target-family/publication leakage where relevant. Null designs preserve study dependence and network/coverage structure; naive metabolite shuffling is not automatically valid.

## 6. External evidence boundary and honest outcomes

Existing imported study FC/p/q tables remain display/concordance-only under the source contract. They cannot enter this extension through a reference-resource label. A reference perturbation signature has its own curated dataset provenance, experimental context, preprocessing/selection, overlap and approved comparison protocol. Reusing the evaluation Study as its own reference is refused. Supplied binding/functional/engagement evidence is linked and labelled external, never silently treated as a new experiment or B/C result.

Reference qualification is based on provenance and a reviewed protocol, not table shape. A public curated dataset can qualify after its original experiment/cohort/subject/sample identities or privacy-safe overlap evidence, construction and feature-selection data sources, context, source digest and comparison/validation scope are checked. Feature-ID overlap is expected for matching and is not leakage by itself; using evaluation outcomes/observations to construct/select the reference is leakage. Record overlap at cohort/subject/sample and selection-training-data levels. Unknown relevant overlap makes the signature axis not-assessable with reason `reference_overlap_unknown`; confirmed prohibited reuse raises `D_TARGET_REFERENCE_LEAKAGE`. Neither suppresses independent eligible mapping/evidence axes or silently accepts the signature. Renaming an imported evaluation result to reference cannot bypass this review.

Separate execution availability from scientific interpretation. Proposed execution states: eligible, incomplete_context, unsupported_entity, resource_unavailable, insufficient_coverage, inference_unapproved, completed. Each metabolic-compatibility, functional-perturbation and binding/engagement axis independently records coverage and assessability (assessable, partly_assessable, not_assessable or not_applicable), reason and evaluated evidence classes. Summary execution success cannot imply that every axis was assessed. Interpretation records compatible, conflicting, mixed or indeterminate **only under a stated rule with underlying evidence**, and may remain unclassified when that rule is unapproved. Missing coverage yields indeterminate/unavailable, not disproved; an incompatible direction is not necessarily evidence of no binding. An effect is neither causal nor target-specific merely because an enrichment or integration component is significant.

Errors identify the relevant target/source/context: `D_TARGET_UNRESOLVED`, `D_TARGET_CONTEXT_MISMATCH`, `D_TARGET_UNIVERSE_UNDECLARED`, `D_TARGET_EXPECTATION_UNSUPPORTED`, `D_TARGET_REFERENCE_LEAKAGE`, `D_TARGET_INFERENCE_UNAPPROVED`. Optional unavailable modules preserve B/C and the rest of D; requested-required completion follows the declared shared status policy.

## 7. Two synthetic examples and acceptance plan

Example 1: two fictional enzymes share a measured downstream product, while the distinguishing substrates are unmeasured. Both receive the same limited evidence profile; report an unresolved target group. Add a synthetic discriminating measurement with an explicitly specified mechanism to test that distinction, not a claim that biological inference always succeeds.

Example 2: a fictional receptor has a reference perturbation signature in one cell context, while the Study measures another biofluid/time context. Expose the mismatch and prevent direct-binding claims. Compatible multi-omics observations can support an exploratory hypothesis; changing the C factor sign leaves the abundance-effect interpretation unchanged.

Planned tests: namespace/species/isoform/complex ambiguity; no mapped metabolites; a genuinely contradictory signed expectation; unsigned relation refusal; reverse contrast; adduct/database duplication; dependent B/C evidence; alternative targets with equal profiles; incomplete source selection; stale resource/signature hashes; mismatched contexts; leaking discovery/validation reference; imported-result bypass; one-Block/metabolomics-only availability versus N-block corroboration; unavailable versus negative evidence; null controls and weak signal without forced recovery. Comparative methods require held-out known perturbations and external context validation with uncertainty and explicit failure limits. No fixtures contain real study identifiers or constants. Nothing has been run.

## 9. Decisions, contribution and readiness

Proposed D-ADR07: target investigation as an opt-in D capability, all three modes represented, profile-first assessment; quantitative discovery/ranking remains conditional. D-ADR01 covers new public evidence inputs, D-ADR03 identity/context and D-ADR04 target-level inference/multiplicity. R, dependency, reference rights, resource pinning, protected interfaces and final independent review gates remain unchanged. No new dependency or permission is inferred from a resource being named.

Existing methods already connect metabolomic perturbations to mechanisms. The proposed contribution is an auditable, Study-aware service comparing explicit target hypotheses and their alternatives across available blocks. Novelty, universal coverage, causal identification and calibrated binding prediction are not claimed.

Review readiness requires primary-source evidence checked, source/claim distinctions reviewed, public schema and scientific choices settled, target-specific failure behavior and tests specified, and independent review of this new extension. Implementation readiness further requires all original G0 requirements. This document is a concrete proposal under development; no drug/target choice is required to design it, and prior Opus approval of the earlier architecture must not be represented as approval of this addition.
