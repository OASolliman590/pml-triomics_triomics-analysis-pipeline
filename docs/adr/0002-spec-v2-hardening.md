## Preserve
The September 6 settlement: R core plus isolated Python MOFA; same molecular
representation within each Analysis/context; signed paired deltas; distinct
mean-retaining analyses; immutable fit/apply; B-owned clinical fits; fixed
per-block scalar-claim BH; explicit DIABLO consensus; typed target evidence;
conditional resource adapters; the protected interfaces and all 41 ticket IDs.

## Harden
- Normalize scattered proposals into spec-v2. No operator must arbitrate between
  an accepted header and a superseded draft paragraph at execution time.
- Replace publication/unknown-language blockers with verified repository facts.
  Public visibility requires conservative data handling, not a visibility change.
- Freeze concrete configuration, schemas, module seams, errors, output shapes,
  acceptance and ownership. Scientific study parameters remain explicit inputs.
- Move generic profile/preprocessing infrastructure into A-T03; A-T04/05/06 become
  independent policy implementations rather than depending on proteomic code.
- After common baseline/evaluation seams, categorical, continuous and MOFA adapters
  may proceed in disjoint files. This removes scheduling edges, not scientific gates.
- Retain nine audited milestones. Allow dependency-safe work across components
  when the required contracts and review gates are accepted; no global A/B/C/D
  mutex when there is no dependency. Report/vignette milestone order is preserved.
- Sol high coordinates; Luna max codes; Terra max documents; Astra low audits
  freeze and each milestone. Actual model/effort IDs must be discovered on host.

## Deliberate limits
No new quantitative target-ranking estimator is selected: D-T14 retains a genuine
method/protocol gate. Native MOFA enrichment, BioPAN, incremental clinical prediction
and unsupported clinical response families retain explicit qualifications. Null
or weak-signal non-recovery is not automatically a pipeline bug. No data or runtime
validation is asserted. This bundle was not pushed by the drafting assistant.

## Change control
A post-audit amendment records old/new hash, affected requirements/packets,
scientific rationale, test impact and review. Material semantic changes cannot be
hidden in a worker's implementation or a documentation edit. Pure scheduling
changes still require ownership/DAG revalidation. No force push or history deletion.

## Explicit variance clarification
PCA block projection and supervised concatenation nested training-score subspace
fractions are defined in C_INTEGRATION.md, with numeric SSE oracles. This is the
settlement's allowed reviewed reconstruction route, not a claim that prcomp/PLS
natively emits block variance. Native DIABLO/MOFA semantics remain unchanged.
