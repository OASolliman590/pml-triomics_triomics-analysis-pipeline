# RDY-002 — Prespecified C-07 synthetic qualification protocol

**Status: proposed for Sol review; no runner, fits, qualification or acceptance in this packet.** The companion [machine-readable plan](RDY-002-c07-protocol.json) fixes the design below before outcomes are inspected. This is a small synthetic method-and-runtime qualification, not evidence about a patient population, clinical performance, biological truth, or a study hypothesis. C-07 is evidence within C-06, not an additional ticket. RDY-001 authorized subsequent bounded protocol work; it did not qualify these methods ([approval](spec-readiness-approval.json)). The frozen [validation](../../../discovery/spec-v2/VALIDATION.md) and [integration](../../../discovery/spec-v2/C_INTEGRATION.md) contracts govern if this document is ambiguous. The earlier C-02 and M6 receipts are software acceptance records, not C-07 results ([C-02](../reviews/2026-10-19-c02-m5-acceptance.md); [M6](../reviews/2026-10-22-m6-sol-acceptance.md)).

The design uses three separate lanes: full-synthetic-cohort **exploratory** MOFA versus concatenated PCA for known-factor recovery, nested continuous block.spls versus concatenated PLS, and nested categorical DIABLO versus concatenated PLS-DA. MOFA is not used to predict held-out outcomes. The MOFA+ paper describes a multi-view latent-factor framework [Argelaguet et al. (2020/05), Abstract]; DIABLO is a supervised multiblock classification method [Singh et al. (2019/01), Abstract]. Wrapping model selection inside the outer test split addresses the selection-bias issue illustrated by Varma and Simon [Varma and Simon (2006/02), Abstract]. These sources motivate the division of roles; they do not validate the numerical thresholds selected here.

## Fixed synthetic population and scenarios

Use precisely ten dataset seeds `51001` through `51010`, distinct from B-T04's `1001:1400`. Within a seed, generate **one** indexed hypothetical cohort, its latent variables, outcome, noise matrices and maps; the four regimes are counterfactual assay measurements on those same synthetic units, not separate cohorts renamed to pass a check. The order of random draws, parameters and matrix orientation are fixed below. Runs for different seeds are independent simulation replicates, not repeated measurements on real participants. There are 64 units, one sample per subject, two blocks `alpha`, `beta`, 20 features per block, no missing values and no replicate visits. Keys are `unit_001`…`unit_064`, with matching subject keys `subject_001`…`subject_064`, and `alpha_f01`…`alpha_f20`, `beta_f01`…`beta_f20`. Arrays are feature-by-unit, in that order.

Use R 4.6.1, `RNGkind("Mersenne-Twister", "Inversion", "Rejection")` and `set.seed(s)` once per seed. In order, draw independent standard-normal 64-vectors `g`, `u`, `h`, `e_y`, then 20-by-64 matrices `E_alpha`, `E_beta` from `rnorm(1280)` in R's column-major order. Define `z = 0.8*g + 0.6*u`, `y = z + 0.5*e_y`. Sort `y` ascending, breaking exact ties by unit key; assign the first 32 `control`, remaining 32 `case`. Use this *same* `y`, class label, `z`, `g`, `h`, and error matrices for every regime of a seed. The rank-based class construction gives exactly balanced classes but couples labels across units; it is a simulated binary target, not an independent Bernoulli sampling design. Neither `g`, `u`, `h` nor `z` is a predictor column supplied to a model.

For `j=1..20`, let `w_j = (-1)^(j-1)` for `j <= 10`, otherwise 0; let `v_j = (-1)^(j-11)` for `j >= 11`, otherwise 0. For each block `b`, with that block's `E_b`, set:

| Regime | Assay `X_b`, feature-by-unit | Interpretation |
|---|---|---|
| null | `E_b` | Gaussian assay noise independent of the generated outcome. |
| weak_signal | `0.15 * outer(w,z) + E_b` | Weak planted shared signal; no required recovery or prediction threshold. |
| strong_signal | `2 * outer(w,z) + 0.5 * E_b` | One identifiable shared factor in the population covariance with spherical independent residuals; prespecified positive control. |
| adversarial | `2 * outer(w,g) + 2 * outer(v,h) + 0.5 * E_b` | Two equally strong population directions; `g` affects assays and, through `z`, the outcome. `h` is an independent nuisance. |

The same `w` and `v` are used in both blocks. The adversarial scenario exposes a batch-like common cause and a competing direction: prediction can be good because of `g` even though the measured signal is not a direct loading on the `u`-dependent part of `z`. This is a constructed confounding example, not a real-study causal inference. The two adversarial population directions have equal eigenvalues: finite-sample individual factor orientations need not be stable. Matching and sign alignment are scoring operations after fitting, never interventions on training or targets. There is no SNR calibration run, outcome-driven parameter change or permutation in this first cycle.

## Matching, split and preparation

For each dataset seed and predictive lane, build one `SplitPlan` via `triomics_nested_split_plan` with `n_outer=3`, `n_inner=2`, `seed=44001`, `target="outcome"`, `unit_ids` and `subject_ids` in the fixed order above, `temporal_order=NULL`. For continuous outcomes use `stratification=NULL`; for categorical outcomes use the fixed class labels. Store the exact plan and its actual `creation_hash`. Both methods and all four regimes within a seed/lane must use that *identical plan object*, not merely an equal fold count. Check every subject is in exactly one outer test fold, every inner fold lies within its parent training set, every applicable categorical training/test fold has both classes, and hashes verify. Do not reduce folds to repair a violation.

For seed `s` and lane `L` (`continuous` or `categorical`), use `study_id=sprintf("rdy002-synthetic-%d",s)`, `analysis_id=sprintf("rdy002-%d-%s",s,L)`, predictive root `preparation_context_id=sprintf("rdy002-predictive-%d-%s",s,L)`, descriptive root `sprintf("rdy002-descriptive-%d-%s",s,L)`, and predictive `representation_id="fold_prepared"`. The C-02 fold contexts append `__<fold_id>` to the predictive root; verify that lineage and retain the actual per-fold state hashes. Assemble each regime using these identical synthetic identities and the same preparation recipe; use a separate state/output directory for each seed/regime/lane/method, and no cross-regime fit-state cache. Each block has the six `none` preparation operations in the C-02 fixture: validate, filter, derive, transform, normalise and impute. Thus all generated values enter preparation without imputation or data-dependent feature filtering. Let each adapter center and scale its features from its **own training units** (`scale_features=TRUE`); the common complete data make per-fold input feature sets equal. For predictive runs, train and apply all learned adapter transforms and feature selection separately inside each inner and outer training set. Use distinct descriptive and predictive context IDs, as required by C-02. Never use full-cohort descriptive transformations in predictive fits.

For each paired comparison, require equal ordered sample and feature maps, preparation context, representation, outcome values, actual plan object/hash, and matrix hashes. Across scenarios the sample/feature maps, logical preparation recipe, representation, outcome and split stay fixed but the assay values necessarily change; save a separate SHA-256 for each scenario's two input matrices and prepared fold states. This distinguishes matched synthetic identity/recipe from identical data. C-06's `triomics_c06_evaluation_evidence` currently checks one identical `match_context` for **all four** regimes as well as each candidate/baseline pair, including `split_plan_sha256`; it does not itself bind the scenario matrix hashes. Its separate `triomics_c06_compare_integrations` comparison requires identical actual matrix hashes, so invoke that only on methods from the *same* scenario, never across changed scenarios. Before native C-06 publication Sol must review whether the scenario-specific source artifacts and common synthetic cohort are sufficient for that immutable-context claim. If not, leave native C-06 publication blocked and report the exact seam; do not force equal hashes or modify the contract. Treat these source hashes as required qualification evidence even where the current C-06 object does not carry them.

## Native calls and metrics

Use the registered adapters and actual `evaluate_pipeline`, never direct native predictions presented as an `EvaluationResult`. Pin the qualified runtime to R `4.6.1`, mixOmics `6.36.0`, MOFA2 `1.22.1`, mofapy2 `0.7.5`; record exact executable/library hashes, other dependency versions, OS, BLAS, hardware and thread settings. MOFA2 was not loadable from this drafting shell's default library; the run must locate and verify the accepted isolated environment before starting its lane. Do not substitute a release or install packages as part of this protocol.

**Exploratory:** Fit `concat_pca` with `scale_features=TRUE`, `block_scaling="none"`, `selection=list(rule="none")`, one component in null/weak/strong and two in adversarial. Fit `mofa2` on exactly the same resolved, full-cohort block values, IDs and feature keys, with `scale_features=TRUE`, Gaussian likelihood for both views, one group, no outcome, matching component counts, `mofa_convergence="medium"`, `mofa_seed_repeats=1`, and `mofa_training_options=list(maxiter=1000, stochastic=FALSE, gpu_mode=FALSE)`. Run the MOFA adapter **twice separately** per dataset/regime using seeds `s+100000` and `s+200000`, each with a distinct model path; preserve both native models, effective options, outputs, and save/reload verification. All other model/data/training options are the pinned MOFA2 1.22.1 defaults as resolved by the installed adapter; capture them before the first fit and compare subsequent runs to that snapshot except for declared seed, factor count and model path. If the required options or pinned defaults cannot be verified, mark that lane unavailable and do not fit. If actual convergence cannot be verified, record it as unknown and block a stronger convergence claim. No extra optimization retries are authorized.

Align rows by unit ID. For strong controls, compute `abs(cor(score_1, z))` separately for PCA and the **primary** MOFA fit; if zero variance, missing factor, non-finite score or a fit error occurs, the attempted seed is a recovery failure. For each method the prespecified engineering check is correlation `>=0.9` on at least **9 of 10** seeds, with all ten seeds attempted; a stopped/unrun seed makes the check incomplete. Count a fit failure in the denominator, but separately report that failure; this narrow check does not turn the overall run complete if required fits failed. The secondary MOFA initialization is descriptive sensitivity, not another chance to satisfy the check. This threshold applies only to this identifiable strong construction, not to null, weak or adversarial controls.

For adversarial recovery center `cbind(g,h)` and the two extracted factor-score columns; use rank-revealing QR (tolerance `1e-10`) to form orthonormal `Q_truth`, `Q_fit`. If both ranks are 2, report `sum((t(Q_truth) %*% Q_fit)^2)/2`, the mean squared cosine of the principal angles, bounded [0,1]; otherwise report unavailable and the actual retained rank. Report the 2-by-2 signed score/truth correlation matrix, the best one-to-one assignment by maximum sum of absolute correlations (lexicographic tie break), aligned signs and correlations. Also report each method's signed/absolute association to `g` and to `z`, and the correlation between score and `z` after separately residualizing both on intercept plus `g`, with undefined cases explicit. No individual adversarial factor receives a recovery pass threshold. In null/weak report score correlations, retained factors, variance definitions and between-initialization within-dataset absolute score correlation; for adversarial report subspace agreement across initializations. Never compare scores across different dataset seeds as if units were the same realized observations. Variance diagnostics remain separately labeled by each native definition; do not rank unlike definitions.

**Continuous:** `mixomics_block_spls` versus `concat_pls`, using `evaluate_pipeline` with response `list(column="outcome",type="continuous")`, `scale_features=TRUE` and the same ordered candidate grid: `ncomp=1`, then `ncomp=2`. For block.spls use `block_scaling="none"`, `mode="regression"`, `response_block="outcome"`, `keepY=1`, `prediction_rule="AveragedPredict"`, `score_definition="consensus_mean"`, and `keepX=list(alpha=rep(8,ncomp),beta=rep(8,ncomp))`. The named design matrix is over `alpha,beta,outcome`, diagonal 0 and every off-diagonal 1. `concat_pls` uses its native dense method and the same component candidates, not a contrived sparse baseline. Record inner mean RMSE, selected component and native predictions on original response scale.

**Categorical:** `mixomics_diablo` versus `concat_plsda` with response `list(column="outcome",type="categorical",levels=c("control","case"))`, the same two component candidates and `scale_features=TRUE`. DIABLO uses the same per-component `keepX=8` per block, `score_definition="consensus_mean"`, `prediction_rule="centroids.dist"`, `na_capability="complete_predictor_blocks"`, `tuning_grid_ref="rdy002_components_1_2_keepx8"`, and named predictor design `[[0,0.5],[0.5,0]]` in `alpha,beta` order. PLS-DA uses the same native centroid distance rule and dense predictors. For both lanes, the current wrapper chooses the lowest mean inner RMSE or balanced error among candidates with no inner fit failure and finite scores on every required inner fold; ties choose the first grid entry. A failed inner prediction can still yield a finite metric: categorical failures count as errors and continuous RMSE can use only successful rows. Record these dispositions and flag any such evaluation as not fully qualified even if the wrapper selects it; do not claim that the existing selector excluded every partial inner prediction. Use `max_fits=15` for **each** evaluation: `3 * (2 candidates * 2 inner fits + 1 chosen outer refit)`. No native tuner or test-set retuning.

Retain the actual `EvaluationResult` predictions, fold/candidate histories, failure reasons and state hashes. For each method/seed/regime report the actual model and its internal intercept/majority baseline; compare the **model metric** of the multiblock result to the **model metric** of the separate concatenation result, not to C-02's intercept/majority baseline. Continuous metrics are RMSE `sqrt(mean((y-yhat)^2))`, MAE `mean(abs(y-yhat))`, and `1-SSE_model/SSE_training_intercept`, with each intercept fitted only on the corresponding outer training set. C-02 continuous metrics use successfully predicted rows only: always publish 64 as the planned denominator plus eligible, ineligible, predicted and failed counts, and label conditional coverage. Categorical balanced error is the mean of the per-class error rates over declared classes; failed predictions count as errors within their actual class, and the full confusion table includes a `<failed>` column. Publish accuracy and counts per class. AUROC is unavailable for these label-only rules. For matched deltas use candidate minus concatenation RMSE or balanced error, lower being better; publish only over an identical, explicitly stated prediction set and treat any partial-coverage comparison as descriptive. No predictive metric is assigned the B-T04 `.08` false-discovery bound.

## Verification, uncertainty and stopping

Two additional prespecified leakage mutation checks reuse the original strong-signal seed `51001` candidate evaluations and each rerun one full evaluation: in `outer_01` test units only add `10` to every predictor cell and add `100` to continuous outcomes or flip categorical labels, retaining the original split plan. Compare the corresponding outer_01 training preparation hashes, chosen candidate and model-state hash before and after; only unchanged training state is a pass. The mutations may alter other outer folds, whose training sets include these units; do not compare them. Each mutation rerun has `max_fits=15`, so it adds at most 30 native fits. If the original evaluation is failed or absent, record that check unrun; never construct a stand-in. Also exercise no-fit negative checks: a C-06 candidate/baseline split-hash mismatch must produce `C_EVAL_CONTEXT_MISMATCH`, and an all-missing feature supplied to the MOFA validator must produce `C_NA_CAPABILITY`. Their verdict is separate from their refused execution status; a refusal is not a completed model.

The 10 independently generated datasets are the Monte Carlo resampling unit. Report seedwise results, counts, median, range, and paired differences. When **all ten** paired seed results for a metric are valid, perform 2,000 paired nonparametric bootstrap draws of 10 seed indices with replacement using R's declared RNG and seed `909991`; use the same indices for candidate and baseline, and report 2.5% and 97.5% quantiles (R type 7) of the mean paired difference as a descriptive Monte Carlo interval [Efron (1979/01), Section 1]. If any pair is failed/unrun, do not bootstrap a cherry-picked complete subset; report its count and values without that interval. For the strong recovery count, a two-sided exact 95% binomial interval may be shown only when all ten are attempted, counting attempted failures as nonrecoveries; label it as a very imprecise model-based simulation interval, not a population or FDR guarantee. The fixed seeds and shared random numbers pair methods and regimes within a replicate; observations within a replicate and overlapping training folds are not independent studies. Report `EvaluationResult$uncertainty` as returned (`not_estimated`); the seed bootstrap is a separate qualification summary, not a patient-level confidence interval. Ten seeds cannot establish FDR control, coverage, robustness across many studies, or an adequately powered comparative benchmark.

Reserve budget **before** launching each native call. The 160 main predictive evaluations reserve `160*15=2400` fits; 40 PCA fits plus 80 separate MOFA fits reserve 120; two mutation evaluations reserve 30. Maximum **2550** native fits, below the requested 3000. No-fit validation tests consume zero; any additional native test or fit requires a separately reviewed budget amendment. One heavy qualification job at a time, one native fit at a time, and BLAS/OpenMP thread counts of one. Global wall-clock cap 21,600 seconds; per evaluation 300 seconds, per MOFA fit 180 seconds, per PCA fit 30 seconds. Check budget and elapsed time before starting each ordered cell. Order by ascending dataset seed; then null, weak, strong, adversarial; within each, PCA, MOFA primary, MOFA secondary, continuous candidate and baseline, categorical candidate and baseline. Run the two mutations after the main cells, continuous then categorical. On a per-call timeout terminate only the run-owned subprocess, record `failed`/timeout and any partial artifacts as nonfinal; on global timeout do not start another cell. The durable reservation is charged even if a killed subprocess cannot report its actual fit count, so no crash can exceed the cap; report actual counts separately when known, otherwise `unknown`, never silently refund. Create all planned cell rows before the first fit, and preserve failed, unavailable and unrun rows with reasons and intended denominators. Do not automatically retry or discard nonconvergent, pruned or negative results.

## Evidence boundaries and future implementation packet

The future runner writes only to a synthetic local qualification root such as `artifacts/qualification/RDY-002/`: protocol/commit/environment hashes, ordered plan and split plans, scenario input/outcome hashes, execution and fit-reservation journal, native options/models, per-fold preparation and model-state hashes, `EvaluationResult` RDS plus canonical summaries, failure ledgers, exact commands/exits/times, score/recovery tables, mutation/negative verdicts and a checksummed final manifest. Save synthetic arrays or reproducible generator input with content hashes; no real data or identifiers enter this root. Write payloads atomically; an interrupted payload never becomes a completed manifest. Record public-synthetic privacy and ensure no synthetic source is an ancestor of real-study artifacts.

Qualification evidence is a standalone result. If Sol later authorizes publication of **same-synthetic-context** C-06 observations, publish a separate four-regime evidence object for each seed and predictive lane. Each complete observation must contain the actual matching `EvaluationResult`, hash and artifact reference, with zero failed predictions; this protocol additionally requires all 64 predictions and no inner prediction failures for complete status. For failed/unavailable/not-run observations the current validator requires a reason and forbids a result/artifact in that observation: retain diagnostics in the separate qualification ledger without fabricating a complete object. MOFA/PCA exploratory scores are never packaged as predictive C-07 observations. The current CLI's `triomics_c06_cli_unrun_controls` constructs unrun records; wiring native actual-control evidence to a published synthetic C-06 output is a distinct coordinator-owned seam, not authorized here. Existing real-study C-07 control status remains whatever actual real-study evidence establishes; synthetic results cannot relabel `not_run` or become real-study ancestors. Future real-study controls need a separately reviewed, study-specific context, disclosure and scientific design.

A bounded Luna scope audit covers only new `inst/qualification/run-c07-qualification.R` and `tests/testthat/test-RDY-002-c07-qualification.R`, plus a packet-owned registration/receipt if Sol requires one. The runner can call the existing C-01/C-05 adapters, `evaluate_pipeline`, split-plan builder and C-06 validator; it must not alter shared registration, schemas, lockfiles, statistical methods or canonical specs. If real native evidence serialization or the CLI publication seam cannot be implemented without shared changes, stop and request a separate Sol-owned scope/change review. Acceptance requires the parent to audit this protocol, authorize an exact runner packet and inspect its failing behavioral tests before any qualification fitting; this document is not that approval. The runner is an installed resource so both source and clean-package tests can load the same bytes with the existing `triomics_test_resource` helper. `tools/` is excluded from R builds; do not skip required tests, duplicate the implementation into tests, or change packaging exclusions to conceal absence.
