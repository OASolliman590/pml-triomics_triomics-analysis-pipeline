## D-T06 — native MOFA enrichment

**Release evidence.** Bioconductor's [3.23 release page](https://bioconductor.org/packages/3.23/bioc/html/MOFA2.html) lists MOFA2 1.22.1; the [1.22.1 reference manual](https://bioconductor.org/packages/3.23/bioc/manuals/MOFA2/man/MOFA2.pdf) identifies release branch `RELEASE_3_23`, commit `6f1b319`, and documents `run_enrichment(object, view, feature.sets, factors="all", set.statistic=c("mean.diff", "rank.sum"), statistical.test=c("parametric", "cor.adj.parametric", "permutation"), sign=c("all", "positive", "negative"), min.size=10, nperm=1000, p.adj.method="BH", alpha=0.1, verbose=TRUE)`. The first choice in each vector is the default. The input is a MOFA object and binary set-by-feature matrix, and the manual calls the null **competitive** and describes adjustment factor-wise. The model fit calls the Python backend; [mofapy2 0.7.5](https://pypi.org/project/mofapy2/0.7.5/) is a separate release, not the implementation of this R enrichment call. MOFA2's [release license](https://bioconductor.org/packages/3.23/bioc/licenses/MOFA2/LICENSE) is LGPL v3; PyPI lists LGPL-3.0 for mofapy2. These software licenses do not establish rights for any biological set collection.

**Implementation lead, not yet release-verified.** The currently browsable official [MOFA2 development source](https://github.com/bioFAM/MOFA2/blob/master/R/enrichment.R) is associated with development [DESCRIPTION version 1.23.2](https://raw.githubusercontent.com/bioFAM/MOFA2/master/DESCRIPTION), not proven identical to 1.22.1. In that source the function obtains model data, scaled weights, and factors; removes zero-variance features; intersects model and annotation features; then removes sets smaller than `min.size`. The comparison is a set versus the remaining intersected features, not D-T04's nominated-list hypergeometric test. It computes absolute feature weights for `all`; directional modes zero the opposite sign, and `negative` takes magnitudes. Directional results with negative set statistics are replaced by p=1/statistic=0 **after** per-factor adjustment. Its permutation branch shuffles feature rows of weights and corresponding data columns, compares absolute null statistics using strict `>` and divides by `nperm` without a plus-one correction. These details are a precise checklist to verify, **not claims established for 1.22.1**. In particular, tests must determine ties, possible zero permutation p values, one-set/one-factor dimensions, missingness, and multiple-testing family behavior on the actual pinned release. A factor sign can flip without changing a factorization: a positive/negative label requires the declared orientation and must not be interpreted as biological activation.

**Small reference proposal.** Construct a public synthetic native model with nonconstant data, a factor having proportional weights `(0.9, -0.8, 0.2, -0.1)`, and at least two sets `{1,2}` and `{3,4}`; use `min.size=2`, `mean.diff`, `parametric`, `all`, and BH. Under the *development-source* pooled two-sample, two-sided calculation, the first set has `t=9.89949493661`, df=2 and `p=0.01005050634`; the complement has the opposite statistic and equal p, so the two-set BH values are equal. These numbers were independently calculated from those four absolute weights using base R, **not obtained by executing MOFA**. Verify the 1.22.1 implementation and native model construction before treating them as expected native output. Add cases for positive/negative orientation, unannotated and zero-variance features, small and overlapping sets, no complement, duplicate/ambiguous mapping, missing data and changed sidecar hashes. With a fixed seed, inspect the actual finite-permutation counts and ties; also test the scientific validity of the chosen null and disclose the scope of adjustment across factors, views and signs.

**Before a Luna packet:** obtain and checksum the exact 1.22.1 release source/binary and runtime, compare its implementation to the leads above, verify the native model plus transformed-data/mask and versioned annotation artifacts and mappings, establish resource rights, predeclare arguments/family/orientation, and execute independently derived reference checks and the packet's negative cases. This session could inspect the release manual but not retrieve its source archive through the available network; the detailed implementation remains an open qualification item.

## D-T07 — BioPAN quantitative comparison

**Availability and rights evidence.** The original [BioPAN paper](https://pmc.ncbi.nlm.nih.gov/articles/PMC7848852/) describes a web tool and points to an [archived publication-time source](https://doi.org/10.17605/OSF.IO/PKD6B) and a [local setup readme](https://osf.io/7g2dx/), identifying the software license as GNU GPL 3.0. The current [LIPID MAPS tool entry](https://www.lipidmaps.org/resources/tools/38?task=7.3) still links OSF source and describes the license as `GNU GPL 3.0 (academic)`. The linked OSF pages returned HTTP 403 in this research session: no archive, readme, executable, bundled dependencies, or exact license text was inspected. The paper is evidence that a historical local route was offered, not evidence of a current maintained runnable release. The directory's parenthetical and paper's wording need clarification for the intended operation; neither an across-the-board prohibition nor permission for this deployment follows from this note. Verify software, included reference-data and LipidLynxX terms, local execution, distribution/derivative obligations and any component-specific terms for the actual snapshot. Do not upload study inputs to the website.

**Input and design.** The current [input documentation](https://www.lipidmaps.org/tool/biopan/doc/step1.html) asks for CSV with lipid species by rows, sample columns containing quantitative molecular concentrations, at least two conditions, and at least two samples per condition. Its [calculation documentation](https://www.lipidmaps.org/tool/biopan/doc/step3_build.html) describes product/reactant ratios, a one-sided comparison between two conditions, conversion of reaction p values to Z scores, and a paired-data toggle. The toggle alone does not establish covariate adjustment, correct subject pairing, repeated-measures support, or a validated statistical model for this study. Verify units, comparable quantitative scales, zero/missing-value handling, lipid identity resolution and pairing order on the exact local implementation; CLR values, precomputed deltas, factor loadings, and adjusted paired claims cannot be silently substituted. The tool's active/suppressed terminology is a predicted pattern, not a measurement of reaction flux or proof of target activity; context and reaction direction remain limited by the frozen D contract. The paper also describes conversion of detailed lipid structures to sum composition, so record any resulting loss of specificity.

**Small reference proposal.** For a documented, supported reaction, use synthetic per-sample reactant concentrations all equal to 10 and product concentrations `(10,20,30)` in control and `(20,30,40)` in interest. The ratios are `(1,2,3)` and `(2,3,4)`. Under an equal-variance one-sided independent t-test, base R gives `t=1.22474487139`, df=4, `p=0.14393206736` and `qnorm(1-p)=1.06281879432`. This is an independently computed **hypothesis for comparison with the native implementation**, not an observed BioPAN result; the documented description does not resolve every implementation option. Use a separate paired case with varied within-subject differences and a deliberate order mismatch, plus zeros, unsupported lipids and invalid scales. Pin all settings, local source, reference tables, version and hashes; compare native table outputs as well as arithmetic. A mismatch requires understanding the native algorithm, not altering the expected value to make a test pass.

**Before a Luna packet:** obtain an accessible, legally usable exact snapshot, inspect its licenses, data and local setup; run the sanitized reference offline; establish quantitative and subject/design compatibility and a reproducible invocation. If any gate remains unsatisfied, preserve the requested route as unavailable and leave unrelated reporting usable.

## D-T14 — research choices, not a method approval

Different research questions produce different numbers. The following are **options for protocol discussion**, not interchangeable estimators or claims about this study:

1. A predefined, measured target-connected feature-set comparison could ask whether molecular evidence is unusually concentrated relative to a declared reference universe. The original [GSEA paper](https://pmc.ncbi.nlm.nih.gov/articles/PMC1239896/) illustrates feature-set inference; extending such a result to a target requires justified target-to-feature links and a null valid for the actual design and dependencies. An enrichment p value is not a probability of binding or proof that a target caused the observed pattern.
2. Matching against independently derived perturbational signatures could ask whether a study signature resembles or opposes a reference perturbation. The original [Connectivity Map study](https://pubmed.ncbi.nlm.nih.gov/17008526/) used expression profiles from treated cultured human cells; transport to a different assay, species, tissue, dose or time is a separate hypothesis. Access, rights, coverage, matching direction and independently documented target identity would all need qualification; resemblance alone is not binding or engagement.
3. A separately calibrated prediction of an explicitly defined target-related outcome is another question. [King et al.](https://pmc.ncbi.nlm.nih.gov/articles/PMC6907751/) studied genetic support and drug-development progression using distinct validation sets and found results sensitive to evidence type and trait matching. This is an example of endpoint- and population-specific validation, not a transferable probability for a target, the present study, or direct binding.

**Decisions and prerequisites:** identify the intended claim, unit and context; choose whether the output is descriptive, a target-level test or a calibrated prediction; approve the exact estimator, eligible versioned target/feature universe, mapping/dependence rules, comparison, null and target-family adjustment. Define handling of missing, contradictory and noncomparable evidence, uncertainty and coverage; preserve the four D evidence axes and B-block q values separately. Specify reference data, labels, rights, ascertainment, overlap and selection history, grouping and temporal cutoffs, validation sample size/precision and prespecified performance or calibration criteria. For predictive validation, place selection, preprocessing and tuning inside the appropriate training partitions and keep subjects, sources and shared evidence dependencies out of the test partition; selection on all samples can bias evaluation ([Ambroise and McLachlan](https://pubmed.ncbi.nlm.nih.gov/11983868/)). Decide what independent biological or clinical evidence would validate the particular claim, without treating this note as a choice of endpoint.

**Small adversarial reference proposal:** before any numerical oracle exists, build a synthetic bounded universe with two targets sharing one feature/source, a duplicate adduct, one contradictory observation, one context mismatch and one unmeasured distinguishing feature. Record source/dependency identity and confirm that missing coverage is not turned into absence, shared evidence is not counted as independent, and descriptive outputs remain separate. Once a method is approved, add an independently calculated numerical case, a protocol-matched null and leakage/overlap and coverage-calibration experiments on the declared validation evidence. A synthetic fixture alone cannot validate biological performance. Without the explicit change record and affected acceptance review required by the frozen D contract, D-T14 remains conditional-unapproved.
