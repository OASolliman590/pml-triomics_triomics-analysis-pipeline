# RDY-006 — proposed regression-verification budget

**Proposal only: no execution approval, audit, fit, enrichment call or acceptance.** This proposes a separate budget for **one clean Git-archive package-check attempt** of a future immutable integrated readiness candidate. It narrows the earlier unaudited, unspent two-gate proposal to the actual required regression gate; it waives no accepted requirement and changes no frozen protocol. RDY-003 requires independent no-fit tests and a clean-archive package check with no required skips, not an additional full-source rerun (`docs/implementation/change-records/RDY-003-c07-runtime-dependencies.md:76-85`). The package check itself runs the packaged tests. Evidence is software regression evidence only: it supplies no C-07, MOFA enrichment, biological, clinical or study-validity qualification.

Before the attempt, confirm independent no-fit source and installed runner-test evidence for the applicable immutable candidate and complete the no-fit supervision preflight below. A fresh Astra review must pass this proposal, the final immutable candidate, the concrete execution subject and that no-fit evidence; Sol then decides whether to authorize the single attempt. The reviewer may reject command-based accounting if it is insufficient.

## Proposed bounded command seam

After all intended product and runner changes are integrated, Sol freezes one commit, a clean `git archive` and SHA-256, the expanded archive and its file manifest. Diff every gate-reachable R, Python, test, helper, fixture, configuration, build/install and script change against the inspected baseline, including subprocess calls and loops. Freeze the exact unfiltered test-file inventory and compare the source and packaged test files. If any new gate-reachable native fit or enrichment call is introduced, one cannot determine whether such a call is introduced, or a required test changes how it invokes native work, **stop and reconsider this budget before execution**. No missing test may be concealed with a filter, skip, dependency removal, mocked backend or weakened assertion. In particular, this proposal permits **zero** D-T06 native enrichment entries and **zero** new D producer fits. If the candidate suite would invoke `run_enrichment`, the package check may not start under this proposal; review its place in RDY-004's existing four-entry budget or amend that protocol first.

The entire proposed native-execution allowance is this one top-level attempt, including its test-internal descendants and prescribed repeated fits. From the expanded clean archive root run once, unfiltered: `Rscript --vanilla tools/check-package.R --root <archive-source> --output <new-package-evidence-directory>`. The wrapper stages source, runs `R CMD build` and `R CMD check`, and copies `testthat.Rout`, `00check.log` and the testthat warning inventory (`tools/check-package.R:65-80,114-164`; `tests/testthat.R:8-29`). Verify the final `00check.log` status is **exactly `Status: OK`**: the wrapper alone does not reject a missing `Status:` line (`tools/check-package.R:156-159`).

This is one reservation, not a numerical fit allowance, a discretionary pool or permission for additional model-producing focused tests, a standalone repeat walkthrough, a separate vignette render, extra native probes, retries or reruns. The in-suite walkthroughs remain required. A failed, timed-out or interrupted package check remains failed; preserve its evidence. No automatic relaunch or refund, including when entry counts are unknown. A later full-source run needs an explicit demonstration of necessity and a separately reviewed budget before execution. Any further native verification likewise needs a new reviewed amendment.

## Preconditions, timing and receipts

Before reservation, verify no competing heavy qualification/verification job and configure concurrency **one**: one package check and one native fit at a time. Set `OMP_NUM_THREADS`, `OPENBLAS_NUM_THREADS`, `MKL_NUM_THREADS`, `VECLIB_MAXIMUM_THREADS`, `BLIS_NUM_THREADS` and `NUMEXPR_NUM_THREADS` to `1`; verify single-thread pools and effective settings in children where applicable. Use the qualified local runtime and environment described in `docs/implementation/milestones/M9.md:11-15`, with a fresh isolated candidate library installed from the same archive; verify its source stamp, library identity, required dependencies and actual environment inheritance in child processes. Use separate local, nonoverlapping archive, package-output, temporary and evidence roots. Set and verify the D-T09 project authority and evidence roots so the positive tests execute. Inspect candidate install/load hooks to confirm setup and process preflight perform no model fits or enrichment. Do not install dependencies, use network access, or supply private study data.

Proposed fixed wall-clock caps: **7,200 seconds for the package check** from supervised launch, and **7,800 seconds overall** from immediately before its reservation through receipt finalization; the check also respects the remaining overall time. M9's retained full-source timestamps show 5,629.61 seconds (`docs/implementation/evidence/2026-11-07-m9-final-gates/source-gate.json:13-15`) as historical context only. Its package receipt records a verification timestamp, not a package start or duration (`package-gate.json:1-7`); **package elapsed is unknown**. The package cap is an engineering scheduling choice, not a measured package duration or guarantee the future check will finish. No-fit setup and preflight occur before this clock; insufficient capacity or failed preflight means the check does not start.

The exact frozen command, candidate and runner, archive/hash, candidate library and runtime identities, test inventories, environment, deadlines, supervisor bytes and no-fit test/preflight evidence must be in the Astra brief. Before native work, a harmless-process preflight must demonstrate deadline enforcement, child/descendant ownership and cleanup, durable reservation through controller failure, and no release/relaunch after ambiguous reservation. Atomically persist the command's reservation before launch; use a child release handshake only after recording PID, creation time and identity. On timeout stop and reap only the verified run-owned process and descendants; verify termination before any subsequent action. If identity or cleanup is uncertain, stop. The requirements and limitations in `docs/implementation/change-records/RDY-003-c07-runtime-dependencies.md:40-74` apply; library presence alone does not prove supervision. Keep the original deadline across interruptions.

The package wrapper buffers native-command output until that command exits and removes its work directory on exit (`tools/check-package.R:50-62,107-113`). A timeout can therefore leave incomplete or absent logs. The reviewed supervisor must preserve available partial check artifacts outside that work directory before cleanup, with a no-fit preflight of that mechanism; mark snapshots partial and any missing output or warning inventory unknown. Never infer that an absent warning is absent from the failed run.

For the reservation retain exact argv, candidate/archive and environment hashes, start/end/deadline, PID/creation identity, exit or unknown, timeout and cleanup proof, test counts, every named warning and disposition, partial files, logs and checksums. Report actual fit entries only if a reviewed, complete cross-process mechanism measures them; otherwise state **unknown**, separately from the charged command reservation. Preserve failed, unavailable and unrun states. Require exit 0, zero failures/errors and zero required skips. Inventory all actual warnings by test and message; any new or changed warning needs explicit disposition.
